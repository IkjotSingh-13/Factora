Problem 21 · Factora team

We don’t ask an LLM whether an article is true.

We extract the claims it actually makes, retrieve evidence for each one, quote the source verbatim, and show how the assessment was calculated. When the evidence is thin, we say “not enough evidence” — that is a result, not a failure.

The failure mode we are designing against

What a language model does

Reads the article, “knows” the topic, returns {"verdict":"false","confidence":0.92}.

  • no source
  • no quote
  • a quote it invents looks identical to a real one
  • confident on claims with zero evidence

What we do instead

Retrieve → align → check that the quote is in the text we fetched → score the verified subset → show the working.

  • a claim without two independent domains gets INSUFFICIENT EVIDENCE
  • every number is reproducible arithmetic
  • every source is a link you can open
An unverifiable quote is dropped and counted. It is never displayed. That is the whole trick, and it is enforced in three places.
notes The point of this slide is that the guard, not the model, is the contribution. If asked “so what does the LLM do here?” — answer: optionally drafting stance labels that still have to survive the guard; the demo runs with the LLM unavailable and the audit trail says so.

Pipeline

S1 extract 3–6 claims→S1g pin to a verbatim article sentence→ S2 retrieve · normalise · rank · dedupe domains→S3 stance + quote guard→ S4/S5 transparent score + report

Claim side

  • opinions and predictions excluded, deduped
  • “X said that Y” is checked as Y; the frame is kept for display
  • a claim that cannot be matched to the submitted text is dropped (claims_dropped_ungrounded)
  • time-sensitive claims get a 18-month freshness half-life

Evidence side

  • 7 adapters: Wikipedia, OpenAlex, PubMed, DuckDuckGo (keyless) + Tavily, Google Fact Check (keyed) + local corpus
  • each fails soft: a dead source is named in sources_failed, the run continues
  • page text fetched for the top few, so a quote can be checked against more than a snippet
notes One HTTP request runs all of it — POST /api/verify. Per-stage status and milliseconds are in the response and on screen, so “which stage was weak?” is never a guess.

The quote guard, in code

1 · at S3
def verify_quote(quote, text):
    q = norm(quote)
    t = norm(text)
    return q in t   # else
                  # dropped_quote = True
                  # stance = NEUTRAL
2 · at the scorer
used = [i for i in evidence
        if i.quote_verified
        and i.quote.strip()]
dropped = len(evidence) - len(used)
# only `used` can move a score
3 · at the article
if not grounded(claim,
                 article_text):
    drop(claim)
# never verified against
# a sentence the article
# does not contain

A hallucinated quote has to survive three independent checks to reach the screen. Snippet-only verification is labelled as the weaker thing it is (quote_scope → chip on the card, warning in the audit, note in the seam report).

notes If a judge asks how we know the guard works: the seam checker counts fabricated quotes (0/10 on the captured snapshot) and the QA runner fails the build if a displayed quote stops appearing in the retrieved text.

One transparent number, and one direction

S = 0.30·C + 0.30·R + 0.20·A
    + 0.10·T + 0.10·K

C credibility   weighted by relevance
R relevance     mean over verified items
A agreement     |sup−ref| / (sup+ref)
                × (1 − e^(−n_domains/2))
T timeliness    from median pub date
K context       quote read in context,
                no quantifier gaps

strength = 0.5 + (S − 0.5)·min(1, n/3)
direction = stance_score ∈ [−1, +1]

Nothing was invented to fill the gap. The stage chips turn amber and say which stage had nothing to work with.

Rules that force it

  • fewer than 2 independent domains → no decisive verdict
  • strength < 0.45 → INSUFFICIENT
  • < 3 domains → shrink toward 0.5, so a thin set cannot look confident
  • real two-sided conflict → CONFLICTING EVIDENCE, resolved before the low-score fallback, and both sides stay listed

Limits, in our words

True today

  • stance is decided by a deterministic lexical aligner by default; an NLI/cross-encoder model would beat it on paraphrase-heavy text
  • snippet-scope verification is weaker than full page text; only the top few pages are fetched
  • English, text-only: no image/video/meme claims
  • a claim nobody has written about stays INSUFFICIENT — no verdict is available at any price

Cut on purpose, in the plan’s order

  • cross-encoder reranking (hook exists in ranking.py, off by default)
  • Qdrant / persistent vector store
  • bootstrap confidence intervals — the score is exact arithmetic instead
  • full-text for every result; extra APIs and LLM query rewrites

Nothing in the protected list was cut: end-to-end demo, quote guard, source links, stance/strength separation, breakdown, insufficient state.

notes Never present the cut list as “coming soon”. It is the plan’s own cut order, executed deliberately, and each item has a named seam where it would slot in.
